# 目标买入价 · 全市场扫描 Top1 · 系统再优化分析

日期：2026-07-08。用户三项需求的设计与执行计划。

---

## 一、目标买入价：从"报收盘价"到"每个策略给出该按什么价买"

**问题**：现在 BUY 信号的参考价=昨收，本质是"昨天涨成这样了"，不是"你该挂多少钱"。
每个策略的买点语义不同，应各自给出**目标买入价 target_buy**：

| 策略 | 买点语义 | target_buy 定义 |
|---|---|---|
| 动量轮动 | 趋势票等回踩再上车 | 回踩带下沿 = max(10日线, 现价−1×ATR)（已有 entry_low，升格为目标价） |
| 20日突破 | 突破确认后回踩颈线买 | 20日高点（突破位回测价） |
| 布林带突破 | 站稳上轨确认 | 上轨价 |
| RSI 回归 | 超卖即是买点 | 触发价（现价即目标） |
| MACD 金叉 | 金叉日确认 | 金叉日收盘价 |

**配套：到价提醒（这才是"目标价"的意义）**
盘中监控从"相对昨收涨跌±2%告警"升级为：**近3日推送过的 BUY 信号，实时价触及
target_buy 时推"到价提醒"卡**（strategy_id=target_hit，走现有去重防轰炸）。
原偏离监控保留（它管的是持仓异动，语义不同）。

## 二、全市场扫描：每天从全美股找 Top1 潜力标的

**能力边界先说清（诚实前提）**：S1 已证明动量类信号在无偏池子上的选股 alpha 很弱；
"判断近期会涨"没有系统能承诺。本功能定位是**候选发现器**：全市场按可解释规则打分，
每天推 Top1（附 Top5 榜单），并且**自动进绩效虚拟盘接受检验**——几周后周报会告诉你
它到底行不行，数据说话。

**实现设计**：
1. **标的全集**：Alpaca `/v2/assets`（免费）拉全部 active+tradable 美股（排除 OTC），约数千只。
2. **两段式抓取控制成本**：先批量拉近 5 日日线 → 按日均成交额筛前 ~500 只流动票(>2000万美元, 价格>5)
   → 再拉这些票 130 日历史算指标。批量多 symbol 请求，请求数 ~100 级，IEX 免费额度内。
3. **打分（可解释、不拟合）**：60日动量(40%) + 距20日高点近度(30%) + 5日量比(30%)，
   排除历史<130日的次新。
4. **推送**：`🔎 全市场扫描` 卡：Top1 加粗展示（附 target_buy=回踩带、止损、财报标注），
   Top5 榜单随卡。Top1 以 strategy_id=market_scan 写入台账 → **绩效周报自动追踪它的胜率**。
5. **调度**：每交易日 07:00 ET（早于盘前早报），misfire 宽限 1h。

## 三、系统再优化分析（第 3 点）

| # | 可优化点 | 说明 | 优先级 |
|---|---|---|---|
| O1 | **data/ 无备份** | signals.db(台账/绩效历史) + bars.duckdb 单副本在本机，盘坏=全丢。加每日备份到另一目录/云盘 | **高（真实风险）** |
| O2 | **实盘-虚拟盘漂移监控** | 绩效周报 v2：信号价 vs 次日开盘价的实际可得价差（度量执行落差） | 中 |
| O3 | **池子季度审视自动化** | 每季度出"池内连续垫底标的"提醒卡，防池子腐化 | 中 |
| O4 | 扫描器负载监控 | 全市场扫描是最重的 job，超时/限流需进 JobHealth 告警(已有机制覆盖) | 随#2落地 |
| O5 | 通知冗余 | 飞书挂了信号就丢，可加 console/邮件 fallback | 低 |
| O6 | Alpaca paper trading 集成 | 真实模拟撮合替代"按信号价成交"假设 | 低（等周报数据） |
| O7 | VPS 迁移 | 摆脱本机单点（用户已有计划） | 用户决定 |

**本轮执行**：一(目标买入价+到价提醒) → 二(全市场扫描) → O1(数据备份)。
O2/O3 留到绩效周报积累数据后。全程 TDD、逐项提交、端到端验证后部署。
