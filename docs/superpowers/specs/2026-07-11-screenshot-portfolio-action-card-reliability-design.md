# 截图持仓、行动卡与生产可靠性设计

日期：2026-07-11  
状态：已批准  
范围：账户与持仓来源、截图识别、仓位预算、盘前/盘中消息、行情网络可靠性、通知可靠性和生产收尾。

## 1. 目标

系统应以用户真实账户而非 10 万美元 Alpaca PAPER 账户生成观察计划，并明确回答“什么条件买、什么价格买、买多少”。用户上传券商截图后，系统通过 Codex CLI 结构化识别并安全更新账户/持仓。每日盘前固定输出一张适合飞书手机端阅读的行动卡；盘中仅在状态变化时提醒。行情和通知的瞬时网络故障必须有界重试且可追踪。

本轮仍是观察/建议系统，不自动向券商下单。

## 3. 资金和仓位规则

### 3.1 硬上限

- `capital_limit_usd = 6000`。
- 账户计算权益为 `min(截图权益, capital_limit_usd)`。
- 可以动用全部现金，不强制保留原有 20% 现金储备。
- 可融资金额最多为资金上限的 20%，即 `max_financing_usd = 1200`。
- 最大组合总风险敞口为 `capital_limit_usd * 1.2 = 7200 USD`。
- 每笔新增计划同时受实际购买力、剩余现金/融资容量、单标的权重、主题集中度、风险预算和累计计划金额约束；最严格的限制生效。
- 不把券商展示的全部购买力视为可用融资额度。

### 3.2 组合级预算

计划生成按优先级顺序逐笔预占预算，后续候选使用扣减后的现金/融资容量，禁止每只候选重复使用同一份现金。截图持仓数量未知时，使用经校验的市值/权重约束新买敞口；涉及已有持仓的精确卖出股数时必须阻断，并说明需要含数量的完整截图。

当前可见持仓均属于半导体/存储主题，主题集中度已接近全部证券仓位。现有 `max_cluster_weight` 必须真正接入执行门控，避免继续叠加高度相关风险。

## 4. 截图账户模型

新增独立、可审计的数据模型，避免把部分截图直接伪装成完整 `BrokerPosition`：

- `portfolio_imports`：图片哈希、来源、模型、上传/观察时间、状态、原始结构化结果、校验错误。
- `observed_account_snapshots`：权益、现金、证券市值、购买力、币种、资金上限、融资上限。
- `observed_positions`：代码、数量/成本/现价（允许为空）、市值或估算市值、权重、盈亏、精度来源。

导入状态为 `EXTRACTED / VALIDATED / PARTIAL / ACTIVE / REJECTED`。完整且校验通过的导入可以原子替换上一份活动截图；部分截图可更新账户摘要并用于组合敞口门控，但不得覆盖已有的完整持仓明细。图片按 SHA256 幂等。

生产账户源新增 `screenshot`。选择该账户源后，盘中任务不得再用 Alpaca PAPER 快照覆盖真实账户。账户源冲突或截图过期时必须 fail closed，不得静默退回 10 万美元 PAPER 账户。

## 5. Codex 截图识别

新增命令：

```text
python -m quant_signal.import_portfolio_screenshot \
  --image <path> [--image <path> ...] \
  --capital-limit 6000 --max-financing-ratio 0.20 --apply
```

命令使用当前订阅可用的 Codex CLI，通过 `--image`、严格 `--output-schema`、`--ephemeral` 和只读沙箱提取结构化 JSON。Codex 在空临时目录运行，输出写入临时文件；提示词明确禁止猜测数量、成本、价格或未展示标的。默认超时不少于 120 秒。

应用前必须验证：

- 所有金额使用 `Decimal` 且非负。
- 权益与现金、证券市值、处理中资金在允许误差内勾稽。
- 报告持仓数与可见去重持仓数一致，否则标记 `PARTIAL`。
- 持仓权重合计与证券市值/权益一致。
- 多张截图的账户摘要一致。
- 数量和成本只能来自截图原文。
- 识别失败不改变上一份有效状态，并生成中文导入回执。

Codex 对话上传的本地附件路径可直接传入该命令。飞书群直接上传图片并自动更新需要另建入站事件接收与图片下载服务，不纳入本轮范围。

## 6. 行情网络可靠性

`AlpacaSource` 使用可注入、可复用的 `httpx.Client` 和连接池，并设置独立 connect/read/write/pool timeout。只对幂等 GET 的 `ConnectTimeout`、`ReadTimeout`、`ConnectError`、`RemoteProtocolError` 做最多三次有界退避；HTTP 4xx 不重试，最终异常继续抛出。

`intraday` 保持整五分钟执行；`execution_watch` 错开一分钟，减少通过本机代理同时建立 TLS 隧道。`execution_watch` 重试耗尽后必须进入 JobHealth，不能捕获后静默当作成功。禁止绕过代理、关闭 TLS 校验或仅无限拉长超时。

## 7. 每日行动卡

指数 Top20、执行候选和完整 blocked 明细继续落库；飞书不再展示宽 Markdown 表格。07:00/08:00 流水线以计算和存储为主，08:15 ET 合并为一张“今日行动计划”：

1. 账户：净值、资金上限、现金、持仓比例、融资上限、数据来源和时间。
2. 今日结论：可执行/等待/暂不交易数量。
3. 可执行或等待：最多 3 只，每只显示触发条件、买入区、最高限价、股数、金额、止损、止盈和有效期。
4. 次选观察：最多 2 只。
5. 持仓动作：只列必须止损、止盈、减仓或数据异常的标的，最多 3 只。
6. 暂不交易：按中文原因计数汇总，不逐只展开。
7. AI 简评：主线、最大风险、今日倾向，最多 3 点/300 个中文字符；AI 不得修改量化价格和数量。

飞书卡片改用渠道无关的分段模型，每段渲染为独立 `div` 并加入留白/分隔线，保留 `body_md` 兼容旧通道。AAPL 若出现，只能标为“未持仓新买候选”。

盘中同一五分钟周期的状态变化合并成一张卡，止损优先；没有状态变化不推送。普通状态不按买入价上下浮动反复提醒。

## 8. 通知 outbox 与币种安全

执行事件采用 outbox：事务内写 `PENDING` 和不可变渲染快照，事务外发送；成功标记 `SENT`，失败记录次数、错误和下次重试时间。每轮先重试到期的 `PENDING`，保证飞书瞬时失败不会永久丢失。

候选必须携带真实币种。当前账户只对券商支持的 USD 美股输出股数；HKD/KRW 等非 USD 标的在没有新鲜 FX 和对应市场适配器前标记 `UNSUPPORTED_MARKET`，不得用美元资金直接除以本币价格。

## 9. 生产收尾和验收

- 迁移 Windows Scheduled Task 到可无人登录启动的配置；若当前权限不足，部署检查必须明确失败并保留现有可运行任务，不做半成品替换。
- 清理运行数据的 Git 跟踪策略，不覆盖用户现有 README 修改。
- 使用测试驱动覆盖：截图 Schema/勾稽/幂等/部分导入、账户源切换、6000/7200 硬上限、累计预算、主题门控、AAPL 未持仓、网络重试与非重试错误、任务错峰、卡片上限、outbox 重投、币种阻断。
- 验收顺序：聚焦测试、全量 pytest、mypy、当前截图真实导入、盘前/盘中端到端演练、生产重启、任务状态和日志核验。

完成标准：生产不再基于 100,000 USD PAPER 账户输出股数；当前账户显示 5,995.52/6,000 USD，AAPL 不在持仓；计划不突破 7,200 USD 总敞口；截图重复上传幂等；飞书盘前固定一张清晰行动卡；瞬时 TLS/飞书失败有界重试并纳入健康状态。
