# 推送可靠性标注设计（账户快照超龄提醒 + SELL 信号低可靠性标注）

## 1. 目标

1. **账户快照超龄提醒**：真实账户状态靠截图导入维护，超龄后执行建议其实在用
   旧账本计算——在每日行动卡（execution_brief）上显式提醒"该发截图了"；
2. **SELL 信号可靠性标注**：回测已证明 SELL 端 20 日胜率仅 32–42%（牛市窗口），
   但推送时与 BUY 视觉权重相同——按"如实报告"原则在卡片上标注，不静默降权、
   不改变信号生成与去重逻辑。

## 2. 设计

### 账户快照超龄提醒

- 阈值复用现有 `execution_plan.screenshot_max_age_hours`（已用于 sizing 的
  fail-closed），不新增配置；
- execution_brief 组卡处：读 `ledger.latest_observed_account()` 的
  `observed_at`——缺失或超龄时在行动卡账户段追加一行：
  `⚠️ 账户快照已 {N} 小时未更新（阈值 {M}h），股数建议基于旧账本，请发送新截图`
  （缺失时提示"从未导入截图账户"）；
- 纯展示层追加，不改变 BLOCKED/sizing 判定（那套 fail-closed 已存在）。

### SELL 信号标注

- `signal_card`：`direction == SELL` 时正文追加一行
  `⚠️ SELL 信号历史胜率偏低（回测 32–42%，牛市窗口），仅供参考`；
- 早报/日报表格（premarket report）：存在 SELL 行时表格下追加同一句脚注
  （每卡至多一条，不逐行重复）；
- 文案为常量，集中放在 cards.py，回测结论更新时只改一处；
- 不加配置开关（标注是"如实报告"的一部分，不该被关掉）。

## 3. 测试

- 行动卡：快照新鲜/超龄/从未导入三种情形的文案有无
- signal_card：SELL 有脚注、BUY 无
- 早报：含 SELL 行有一条脚注、纯 BUY 无、多 SELL 行仍只一条

## 4. 非目标

- 不做 SELL 推送开关或降权（改变行为需先有新回测证据）
- 不做截图提醒的独立推送任务（挂在已有行动卡上，避免新增噪音通道）
