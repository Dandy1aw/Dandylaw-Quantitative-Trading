# 期权榜单展示优化设计（到期日排序 + 同标的去重）

## 1. 目标

飞书卡片上的 CALL/PUT Top10 两段：

1. **同一标的去重**：每侧同一 underlying 只显示成交量最高的那张合约，避免
   SPY/TSLA 的一条期权链刷满整个榜；
2. **按到期日排序展示**：近月优先（到期日升序，同日内按成交量降序），一眼看到
   最近的热点。

## 2. 核心原则：只动展示层

排名（`rank`）、实质变化判定（`detect_material_changes`）、台账落库、数据质量
门槛（每侧 ≥10 只合格合约）**全部保持逐合约原语义不变**。理由：

- 异动判定按合约对比上一轮，去重后对比会把"同标的换了一张主力合约"误判成
  巨幅增量，破坏刚修完的求真语义；
- 台账存原始 50 名候选，展示规则以后随时可调，历史数据不受影响；
- fail closed 门槛继续基于原始合约数，展示层去重导致可显示行数 <10 是正常
  现象（不触发告警，如实少显示）。

## 3. 展示选择算法

新增纯函数 `display_top_by_side(snapshot, side, n, *, dedupe, sort_by_expiry)`：

1. 取该侧全部候选（已按成交量排名）；
2. **去重**（`dedupe=true`）：每个 underlying 保留成交量最高的一张（量相同取
   OCC symbol 字典序，保证确定性）；
3. **选取**：按成交量取前 `n` 个 → 这一步保证榜单仍是"热度 Top10"，只是每个
   标的一个席位；
4. **排序展示**（`sort_by_expiry=true`）：对选出的 n 行按
   `(expiration 升序, volume 降序, contract_symbol)` 排列。

> 备选方案（放弃）：直接按到期日优先"选取"前 10。那会让一张量很小的近月合约
> 挤掉量很大的远月，榜单从"热度榜"变成"近月榜"，与频道定位（成交热度观察）
> 冲突。近月优先只影响**顺序**，不影响**入选**。

行首编号使用**原始每侧成交量排名**（如 `#3`），去重+重排后编号不连续是刻意
的——它如实告诉用户这张合约在原始榜的位置。行内 DTE 标注保留。

同一标的在原始榜上还有其他合约进入 Top10 时，行尾追加 `(+N张同标的)`，
不隐瞒被折叠的信息。

## 4. 涉及的修改点

| 位置 | 修改 |
|---|---|
| `options_flow.py` | 新增 `display_top_by_side()` 纯函数 |
| `notifier/cards.py` | `rank_section` 改用新函数；行首用 `#原始排名`；追加折叠计数 |
| `pipelines/option_flow.py` | Alpaca enrichment 的目标集合改为**展示集合**（否则去重后新显示的行没有 OI/报价）；数据质量校验保持原始口径 |
| `config.py` / `settings.yaml` | `option_flow.display_dedupe_underlying: true`、`option_flow.display_sort_by_expiry: true`（都可单独关掉回旧展示） |

“异动聚焦”段不变：它本来就逐合约、已有同标的最多 2 张的限制。

## 5. 边界情况

- 去重后不足 n 个 underlying → 有几行显示几行（数据质量门槛在原始口径已保证
  候选充足，这只是展示密度问题）；
- 0DTE 与近月天然排前，符合"优先看近的"意图；
- 收盘榜/基线榜/盘中榜统一使用同一展示规则（不做 per-phase 差异）；
- 上一轮对比增量（`+X/15m`/`首次可见`）按合约计算，与去重无关，照常显示。

## 6. 测试与验收

- `display_top_by_side`：去重保最高量、量相同 tie-break、到期日排序、
  两个开关独立生效、不足 n 行为
- 卡片：同标的只出现一次、`#原始排名` 非连续、`(+N张同标的)` 折叠标注、
  近月排前
- pipeline：enrichment 目标集合 = 展示集合（去重后新进显示的行有补全）
- 全量 pytest + mypy + 一次真实冒烟（读 Cboe 渲染卡片检查排版）
