# 量化系统可信度与研究闭环优化路线

## 1. 目标

在不推翻现有调度、飞书机器人、市场状态、候选通道、账户风险和成交台账的前提下，将系统从“能稳定生成建议”升级为“每个结论都有可追溯数据、可复现证据和真实绩效反馈”。

本路线不直接复制 `worth-buy-stocks` 的固定权重或阈值，只借鉴其数据契约、回测产物、版本化和前瞻验证方法。

## 2. 保留的现有能力

- 定时调度、任务健康、重试、持久化 outbox 和飞书交互。
- 账户截图导入、持仓纪律、执行计划、风险集群和融资约束。
- 基于均线、市场宽度和波动率的市场状态判断。
- 趋势延续、强势回调、区间修复三条候选通道。
- 持仓期权情报、全市场期权热度、真实成交持久化和 FIFO 绩效基础。

## 3. 工作包与顺序

### 阶段 A：数据可信度（P0）

1. 日线增加 `final/live` 状态、复权口径、抓取时间和数据版本。
2. 生产选股和研究回测只允许读取 `final` 日线；盘中快照仅用于展示与执行参考。
3. 建立交易日覆盖记录、缺口计划和断点回补。
4. 研究默认使用只读 `cache-only` 模式，覆盖不足时失败，不在回测过程中联网补数据。

### 阶段 B：证据与前瞻闭环（P0）

1. 建立统一研究入口和规范 JSON 产物。
2. 每次运行记录 `model_version`、`config_hash`、`data_hash`、`universe_hash`、成本模型和 point-in-time 状态。
3. 推送前不可变地保存特征、分数分解、市场状态、执行计划和模型版本。
4. 在 21/63 个交易日后自动评价，禁止回写历史决策记录。

### 阶段 C：统一决策层（P1）

保留三条入场通道，在其上增加可解释的统一决策层：

1. Alpha 排名：风险调整动量、12-1 动量、相对 SPY/QQQ 强度和 Kaufman 效率。
2. 风险否决：市场状态、趋势、财报窗口、流动性和风险集群。
3. 质量确认：趋势质量、量能、过热程度和数据完整性。
4. 入场时机：由现有三条候选通道决定。

权重只能通过开发集、验证集和封存 holdout 的证据晋级，不预设照搬外部项目的固定权重。

### 阶段 D：样本外与真实净收益（P1/P2）

- 接入真实历史指数成分和退市标的，落实 point-in-time 股票池。
- 对重叠收益周期使用 purge/embargo，输出因子 IC、bootstrap 置信区间、换手和成本后收益。
- 统一计入佣金、滑点、汇兑、分红拆股、部分成交和计划/实际执行偏差。
- 增加特征缺失率、分数分布、覆盖率、分市场状态表现和数据新鲜度监控。

### 独立快速改进：期权热度按标的聚合

将当前全市场期权热度卡的 Call/Put 分榜合并为标的级热度榜，但不改动底层逐合约台账、异动检测和告警语义。详细设计见同日《期权热度按标的聚合展示设计》。

## 4. 实施批次

1. **批次 1**：期权热度聚合展示；行为边界清晰，不影响交易信号。
2. **批次 2**：日线数据契约、覆盖记录和研究只读模式。
3. **批次 3**：统一研究产物、模型版本和前瞻评价。
4. **批次 4**：统一决策层与严格样本外晋级。
5. **批次 5**：真实净收益、全局 API 预算和模型漂移监控。

每个批次独立设计、测试、验证和发布，不使用一次大规模重写同时改变数据、策略和展示语义。

## 5. 总体验收原则

- 数据不完整时显式失败或降级，不使用零值或推测值补齐。
- 同一数据、配置、股票池和模型版本必须生成可对比的确定性产物。
- 开发集、验证集和 holdout 边界固定，失败的方案保留拒绝记录，不在 holdout 上继续调参。
- 任何“收益”必须标明理论/模拟/真实、毛收益/净收益、成本口径和数据覆盖。
- 生产发布前运行定向测试、全量测试、静态类型检查和真实只读烟雾验证。
