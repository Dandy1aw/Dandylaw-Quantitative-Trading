# 中国市场 A 股与基金榜单设计

日期：2026-07-12  
状态：已确认，待按实施计划开发  
范围：沪深北 A 股、场内 ETF/LOF、场外公募基金的发现、排名、回测、持久化与飞书展示

## 1. 结论

在当前单进程服务内新增一条**独立中国市场纵向链路**，复用已有的配置、调度、SQLite 台账、DuckDB、飞书通知、机器人查询、健康检查和回测框架，但不复用美股的交易日历、代码格式、美元成交额、SPY 基准或整股数量规则。

首版提供三套不可混排的榜单：

1. `CN_A_SHARE`：沪深股票主榜，北交所作为独立观察子榜；
2. `CN_EXCHANGE_FUND`：场内 ETF/LOF，按宽基、行业主题、Smart Beta、债券、黄金商品、跨境/QDII 等类别排名；
3. `CN_PUBLIC_FUND`：场外公募，按被动指数、指数增强、主动权益、混合、债券、QDII 等类别排名。

当前账户只有 USD 截图状态，没有人民币账户、真实 A 股持仓、费用与券商交易能力，所以首版是**只读观察系统**：输出排名、数据日期、可交易性和风险标签，不输出建议股数，不自动下单，也不让 AI 补造买入价。未来接入人民币账户后，另立 `cn_execution` 方案。

## 2. 为什么不直接扩展现有美股扫描

### 方案 A：直接扩展 `pipelines/market_scan.py`

优点是改动小，能快速显示六位代码。缺点是现有链路默认 NYSE 日历、America/New_York 时区、USD 成交额、SPY 基准、1 股取整和美股代码语义；六位代码还会在股票与基金之间碰撞。复用后很容易得到“能跑但语义错误”的榜单，因此否决。

### 方案 B：同一服务内新增独立中国市场纵向链路（采用）

复用可靠性基础设施，同时隔离数据、日历、标识、因子、交易规则、卡片与绩效口径。单机部署成本没有明显增加，关闭 `china_rankings.enabled` 即可完整回退。

### 方案 C：独立微服务和数据库

隔离最强，但当前是单机单用户服务，额外的进程监控、部署、凭证和跨服务一致性成本超过收益。等中国市场数据量或调用频率影响美股任务后再拆分。

## 3. 产品边界

### 3.1 首版目标

- 全量维护沪市、深市、北交所股票元数据和时间点快照；
- 全量维护场内 ETF/LOF 与场外公募基金元数据；
- 每个榜单保留 Top10，推送只显示 Top3 和重要变化，完整榜单由机器人按需查询；
- 每行明确 `as_of`、数据源、覆盖率、榜单规则版本、流动性与风险标签；
- 数据不完整、日期错位、来源不一致或规则未知时 fail closed，不沿用旧榜冒充今日榜；
- 建立点时回测、前向 shadow 记录和榜单命中率/超额收益周报；
- 与现有美股信号、持仓、执行计划、期权和 AI 早报互不污染。

### 3.2 非目标

- 不自动提交、修改或撤销 A 股/基金订单；
- 不把 A 股加入当前 `settings.universe` 或 `execution_plans`；
- 不把场外基金 NAV 当成实时价格，不给场外基金盘中买入价；
- 不把股票、ETF/LOF、场外公募放进同一个综合分数；
- 不用今天仍存续的股票或基金列表回填历史回测；
- 不在缺少历史公告时间时把当日 NAV 当作当日盘中已知信息；
- 不因某个证券主数据缺失而按名称猜测 T+0、涨跌幅、申赎状态或交易单位。

## 4. 统一身份与领域模型

内部使用“市场 + 资产类型 + 真实代码”的 canonical ID，供应商代码只作为别名：

- 上交所股票/基金：`XSHG:STOCK:600000`、`XSHG:ETF:510300`；
- 深交所股票/基金：`XSHE:STOCK:000001`、`XSHE:ETF:159919`；
- 北交所股票：`XBSE:STOCK:430047`；
- 场外公募份额：`CNMF:FUND:000001`。A/C/I 是独立字段；存在独立真实份额代码时，每个代码各自成为 instrument，不虚构代码后缀。

新增不可变领域对象：

- `ChinaInstrument`：canonical ID、供应商代码、名称、资产类型、交易所、板块、上市/退市日期、行业、币种、价格精度、交易单位、结算标签；
- `ChinaUniverseSnapshot`：资产类别、`as_of`、抓取时间、来源、完整代码集合、内容哈希；
- `ChinaExchangeBar`：原始 OHLC、调整因子/调整价格、昨收、成交量、成交额、换手率、涨跌停价、停牌与交易状态；
- `PublicFundNav`：基金份额、`nav_date`、单位/累计/复权 NAV、`ann_date`/首次可用时间、申赎状态和来源；
- `ChinaRankingRun`：榜单类型、规则版本、数据日期、覆盖率、来源层级、状态与诊断；
- `ChinaRankingRow`：排名、总分、分项因子、类别/行业、原始价格或 NAV、风险标签和可交易性。

因子收益使用点时调整因子计算，卡片与涨跌停判断使用原始价格。两种价格不得共用一个 `close` 字段。

## 5. 数据架构

### 5.1 数据源顺序

1. Tushare Pro 作为主要批量源，通过现有 `httpx` 直接调用 API；凭证来自 `TUSHARE_TOKEN`，不写入 YAML、日志或快照；
2. AKShare 以已核实的 `1.18.64` 精确版本作为 capability 候选，通过合同后才按资产类别启用整批降级；
3. 交易所/监管网站只用于交易规则、日历异常和元数据校验，不在榜单运行中逐票抓网页。

一次榜单运行只使用一个价格/NAV 提供商。启动时先保存 capability matrix：接口、日期、单位、限价、公告时间、点时元数据和当前权限。主源失败时，只有降级源具备该榜单全部关键字段才允许整批切换；否则该榜单不可用。禁止按单只证券静默混源。降级快照必须记录 `source_tier=FALLBACK`。

### 5.2 存储

新增 `data/china.duckdb` 和 `ChinaMarketStore`，不扩展现有只有 `ticker/ts/OHLCV` 的 `BarStore`：

- `china_instruments`：点时证券/基金主数据；
- `china_universe_snapshots`：每个交易日的可选池快照和哈希；
- `china_exchange_bars`：原始与调整后行情、成交额、上下限、状态；
- `china_public_fund_nav`：NAV、公告日和申赎状态；
- `china_industry_status_history`：点时行业、风险警示、退市与停牌状态；
- `china_product_metadata`：跟踪指数、基金类别、明确的份额关联、规模、申赎状态、结算和费用的点时快照；
- `china_market_rule_versions`：交易单位、价格精度、结算、费用和适用有效期；
- `china_benchmark_bars`：榜单类别使用的基准行情；
- `china_source_capabilities`：接口权限、字段能力和最近探测结果；
- `china_backfill_checkpoints`：历史回填的范围、游标、限频与校验状态。

在现有 `signals.db` 增加带前缀的运行/通知表，不复用 `scan_candidates`，避免同一天中国榜单覆盖美股扫描：

- `china_ranking_runs(run_id, kind, as_of, captured_at, source, source_tier, source_snapshot_id, input_hash, revision, supersedes_run_id, coverage, rule_version, status, row_count, diagnostics_json)`；
- `china_ranking_rows(run_id, canonical_id, rank, score, payload_json)`；
- `china_ranking_bundles(bundle_id, delivery_date, bundle_kind, content_hash, payload_json, created_at)`；
- `china_ranking_bundle_runs(bundle_id, run_id, section_order)`；
- `china_ranking_outbox(event_key, bundle_id, card_kind, status, attempts, next_retry_at, expires_at, last_error, sent_at)`。

run 的唯一约束为 `(kind, as_of, rule_version, input_hash)`：相同输入重跑幂等返回原 run，基金净值补发或修订形成新 `revision` 并以 `supersedes_run_id` 指向旧 run，不覆盖审计历史。08:25 投递任务从多个当前有效 run 生成一个不可变 bundle，并在一个事务中写入 bundle、关联 run 和 outbox；单个 ranking pipeline 不直接创建综合卡 outbox。DuckDB 写入必须显式列名，禁止当前 `INSERT ... SELECT *` 的列顺序耦合。

### 5.3 数据质量门

- A 股有效行情覆盖率至少 98%；
- 场内基金至少 97%；
- 场外公募按类别至少 95%；
- 最新日期必须等于该市场上一预期交易日/上一已公告 NAV 日；
- 日常主源成功运行不调用备源。独立的每周 `cn_source_audit` 抽样调用备源；收盘价中位误差超过 0.1% 或成交额误差超过 5% 时记录 `CROSS_SOURCE_DISAGREEMENT` 并阻断相关榜单。只有两个聚合源时不能武断判定哪一个错误，需交易所第三源或人工复核后再改变单源健康状态；
- 股票/场内基金至少 130 个有效交易日后才可进入首版趋势排名；
- 任一关键字段单位变化、列消失、证券数异常波动或批次混入多个日期均拒绝发布；
- 失败运行保存诊断但不生成 outbox；机器人显示“数据不可用”，不得回退成看似今日的旧榜。

## 6. 证券池与硬过滤

### 6.1 A 股

数据覆盖沪深北全部普通股。首版展示分为“沪深主榜”和“北交所观察榜”，不将流动性与涨跌幅规则差异明显的北交所股票生硬混排。

进入排名前必须满足：

- 上市至少 130 个交易日，近 130 个预期交易日的有效行情覆盖率至少 98%；
- 近 20 日至少 18 个有效交易日；
- 近 20 日成交额中位数至少 3000 万元；
- 原始收盘价至少 2 元、流通市值至少 20 亿元；
- 排除 ST、`*ST`、退市整理、B 股、CDR、长期停牌和当日停牌；
- 当日触及无法成交的一字涨停/跌停时保留诊断但不进入可观察 Top10；
- 实时快照有可信行业字段时，行业最多 2 只进入沪深 Top10，避免单一赛道霸榜；行业字段不可信时按板块和流通市值桶标准化并明确标记，不用当前行业回填历史。

北交所使用相同数据质量门，但独立配置流动性/市值门并独立展示。交易单位与涨跌停价读取每日元数据和限价接口，不按固定百分比推导。

### 6.2 场内 ETF/LOF

按产品类别独立排名，并对同一跟踪指数的重复产品聚类，只保留流动性、规模和跟踪质量更好的代表份额。

默认门槛：

- ETF 上市至少 120 日、规模至少 2 亿元、近 20 日成交额中位数至少 1000 万元；
- LOF 规模至少 1 亿元、近 20 日成交额中位数至少 300 万元；
- 单产品排名窗口历史完整率至少 90%，申购赎回状态正常；整批场内基金 run 的全池覆盖率仍必须达到 97%；
- 溢折价绝对值异常时阻断，LOF 默认阈值 3%；
- T+0/T+1 和交易单位来自产品元数据白名单，不按名称猜测。

### 6.3 场外公募

按基金主产品聚合 A/C/I 等份额，榜单行展示适用持有期和费用，不用多个份额占据多个名次。

默认门槛：

- 进入确定性排名的基金成立至少 3 年，36 个月 NAV 历史完整率至少 95%；成立 2–3 年的基金只进入“短历史观察”，不计算综合名次；
- 当前允许申购，规模、经理任期、公告日期满足类别要求；
- QDII 单独容忍 NAV 延迟并明确标记，不与境内日更产品混排；
- 清盘、合并、暂停申购或关键点时元数据缺失时退出可买观察榜。

货币基金、FOF 和公募 REITs 的收益与交易语义不同，首版只入主数据覆盖报告，不参与排名；后续分别立项。

## 7. 排名策略

### 7.1 A 股的两阶段规则

生产首版使用 `cn_a_v1_baseline`，沿用已理解、可解释的三因子框架，在板块/流通市值桶内做截尾百分位排名；只有点时行业能力通过预检后才增加行业中性：

- 60 日动量 40%；
- 距 20 日高点近度 30%；
- 5 日量能确认 30%。

它用于先验证中国市场数据、过滤、持久化、卡片和绩效链路，不宣称已对 A 股最优。

研究候选 `cn_a_v2_candidate` 仅进入回测和 shadow：

- 跳过最近 5 日的 60 日动量 25%；
- 跳过最近 3 日的 20 日动量 15%；
- 跳过最近 5 日的 120 日动量 10%；
- 行业相对强度 15%；
- 趋势/距 20 日高点 10%；
- 量能确认与流动性各 5%；
- 低波动和低回撤各 7.5%。

只有走完点时样本、滚动样本外和 60 个交易日 shadow 验证后，候选规则才能替换 baseline。禁止因为一次全样本回测较好就直接上线。
若历史行业 capability 不可用，`cn_a_v2_candidate` 不重归一化缺失因子，也不具备晋级资格；baseline 继续使用板块/流通市值桶。

### 7.2 场内基金

只在同类别内比较。首个确定性规则 `cn_exchange_fund_v1` 分两组：

- 指数 ETF/LOF：60 日类别相对动量 25%、20 日类别相对动量 15%、流动性 15%、跟踪质量 15%、低波动 10%、低最大回撤 10%、低溢折价波动 10%；
- 主动 LOF：60 日类别相对动量 30%、20 日类别相对动量 20%、流动性 15%、低波动 10%、低最大回撤 15%、低溢折价波动 10%。

权重全部用同类别的截尾百分位。任一必需因子或点时产品元数据缺失时不参与综合名次，只进入过滤后观察清单；不按零值补分。

### 7.3 场外公募

只使用在 `ann_date` 时已公开的 NAV 和元数据。首个确定性规则 `cn_public_fund_v1` 在类别内计算：1 年相对收益 20%、3 年年化相对收益 20%、3 年 Sharpe 15%、低 3 年最大回撤 15%、低 3 年下行波动 10%、36 月月度胜率 10%、36 月收益一致性 10%。

经理任期、规模、申购状态与费用先作为硬过滤/标签；没有点时历史前不进入历史评分。只有 provider 明确给出 `master_fund_id` 和完整费率表时才自动合并 A/C/I 份额并按预计持有期选代表；能力缺失时保持真实份额代码独立、标记 `份额关联未知`，不按名称猜测。

## 8. 回测与晋级门

### 8.1 点时回测

- 历史回测前先运行可断点续跑的 backfill：按 API 限频分块抓取证券池、状态、行情、调整因子、产品元数据、NAV 与基准，保存游标、输入哈希、权限缺口和年度覆盖报告；不可获得点时行业/ST/费用的区间不得用当前值回填；
- 股票和场内基金信号在 D 日收盘后生成，按 D+1 开盘加保守滑点成交；获得可靠分钟数据后升级为 D+1 09:35–09:45 VWAP；
- 遇停牌、涨跌停锁死、证券未上市、不可申赎或无下一交易日价格时记为 `UNEXECUTABLE`，不得删除样本；
- 股票卖出佣金、印花税、过户费和场内基金费用由版本化成本表提供，回测日期不同可使用不同规则；
- 场外公募按申请截止时间映射到下一可用 NAV，并计入申购/赎回费用和确认延迟；
- 历史证券池、基金份额、经理、规模、费用、申赎状态与公告时间均使用当时快照，避免幸存者偏差和前视偏差。

### 8.2 开发验收与晋级门

功能开发完成的验收是：backfill/断点恢复、点时校验、回测、shadow 记录与晋级判定代码可运行，全套测试通过；它不要求等待未来 60 个交易日才能结束开发任务。

主动推送晋级在后续监控中按资产类别分别判断：

- A 股：20 交易日前瞻 Rank IC >0.02，Top 组合相对中证全指/对应板块基准扣费超额为正；
- 场内基金：按类别的 20/60 交易日前瞻 Rank IC >0.02，Top 组合相对类别基准扣费超额为正；
- 场外公募：6 个月前瞻类别相对 Rank IC >0.02，Top 组相对类别基准和同类 Top 分位命中率均优于基线；
- 每类至少 4 个样本外窗口中的 3 个方向一致，成本翻倍后仍为正，最大回撤相对各自基准恶化不超过 5 个百分点；
- 至少 60 个对应市场观测周期 shadow；允许 provider 故障并 fail closed，但不得有任何覆盖率、日期、单位或混源不合格的数据被发布。

历史从 2018 年开始只是目标范围；若 capability/权限和覆盖报告不支持完整点时数据，回测必须缩短到首个合格日期并在报告中明确，不能伪造全历史。

未达标时仍可保留“研究榜”，但卡片必须标记 `未验证`，不进入每日主动推送。

## 9. 调度与发布节奏

所有中国任务显式使用 `Asia/Shanghai`，与现有 ET/UTC 任务分锁、分 deadline：

- 服务启用时先运行 `cn_calendar_bootstrap`，覆盖前一年到下一年；每周日 09:00 运行 `cn_calendar_refresh`。Tushare 日历必须通过版本化的交易所年度节假日 fixture，并叠加人工维护的特殊休市/开市 override；fixture 每年/发布升级时按上交所、深交所、北交所公告复核，运行时不抓网页。日历不可用或冲突时所有中国 rank/push fail closed；
- 18:30：`cn_exchange_ingest`，补沪深北股票和场内基金；
- 19:15：`cn_exchange_rank_build`，生成 A 股与场内基金榜；
- 22:30：`cn_public_fund_ingest`，抓取已公告 NAV，并整批重试失败源；
- 07:40：`cn_public_fund_catchup`，补抓迟发 NAV；周一生成公募基金周榜；
- 08:25：`cn_rank_push`，工作日推一张紧凑总览；周一由周榜替代日榜，不重复推送；
- 周六 09:30：`cn_ranking_performance`，输出前向表现和数据质量周报。

每个任务使用 `max_instances=1`、`coalesce=True`、显式 `misfire_grace_time` 和独立 `china_lock`。19:15 rank 必须读取成功的当日 `ingest_run_id/source_snapshot_id`，不能仅因墙钟到点就运行。中国行情抓取不得与美股 `market_scan` 共用 deadline 或运行健康基准。为每个关键任务登记独立 SLA（时区、应完成时间、市场日历、最长运行时间、最大陈旧度），Heartbeat 同时检查覆盖率、降级源、outbox 积压和 token/权限错误。

## 10. 飞书与移动端信息架构

为避免再次出现一张卡片几十行的密集输出：

- 主动推送只有一张“国内市场观察”卡：A 股 Top3、场内基金 Top3、风险/数据状态；
- 每项一行，显示代码、名称、类别、分数、关键因子、最新价/NAV 和数据日期；
- Top4–Top10 不主动展开，只显示“回复 A股/ETF/基金 查看完整榜”；
- 新进 Top3、名次上升至少 5 位、标准化分数变化至少 0.75 或可交易状态变化才显示“变化”标签；
- 同类别每天最多一条变化提醒，24 小时冷却；
- 数据源、覆盖率、规则版本和 `观察/未验证/降级源` 信任标签固定放在卡片底部。

机器人新增只读指令：

- `A股`、`A股 半导体`、`北交所`；
- `ETF`、`ETF 宽基`、`LOF`；
- `基金`、`基金 债券`、`基金 QDII`；
- `榜单 600519` 或 `榜单 510300`；
- `国内数据状态`。

机器人只读持久化榜单，不在用户查询时现场全量抓取。首版不把中国榜单送进 Codex 生成价格；后续如接 AI，只允许解释结构化因子与风险，不得改变排名和数值。

## 11. 配置与安全

新增顶层 `china_rankings`，默认关闭，至少包括：

- `enabled`、`shadow_only`、`primary_source`、`fallback_source`；
- 各榜单开关、TopN、覆盖率、流动性和历史长度；
- 数据库路径、调度时间、推送限额和规则版本；
- `include_bse`、类别白名单和风险标签阈值。

`TUSHARE_TOKEN` 仅从环境读取；扩展 `logging_setup.py` 的敏感值/键名脱敏并增加专门测试，不能假设当前只覆盖飞书/Alpaca 的处理器会自动识别 Tushare。原始 API 响应只保存字段、哈希和诊断，不保存凭证。任何配置不完整时只关闭中国榜单，不影响美股服务启动。

AKShare 在 capability 合同通过后以 `1.18.64` 精确版本锁定并延迟导入；关闭回退或关闭中国榜单时不要求加载它，升级版本必须重跑合同。`backup.py`、部署状态脚本和恢复说明必须纳入 `china.duckdb` 与中国榜单表，不能只备份现有 `bars.duckdb`。SQLite 继续使用 backup API；DuckDB 由 `ChinaMarketStore.backup_to()` 在 store 锁和一致性读事务内使用 DuckDB 原生 export/copy 机制创建备份并回读校验，禁止服务运行时直接复制开放中的数据库文件。

## 12. 发布顺序

1. 基础设施：身份、日历、存储、主/备数据源、质量门；
2. A 股 baseline 排名和按需查询，`shadow_only=true`；
3. 场内 ETF/LOF 分类榜；
4. 场外公募周榜；
5. 点时回测、60 日 shadow、绩效周报；
6. 达到晋级门后开启每日紧凑推送；
7. 未来另立人民币账户与执行建议，不与本项目自动合并。

每一阶段必须在全套 pytest、mypy、离线 fixture E2E 和只读真实源 smoke test 通过后独立提交；关闭 feature flag 是回滚路径。

## 13. 主要风险与处理

| 风险 | 处理 |
|---|---|
| 免费/聚合数据字段漂移 | schema 合同测试、原始哈希、整批 fail closed、整批降级 |
| A 股代码与基金代码碰撞 | canonical ID 使用 `市场:资产类型:真实代码`；份额类别放独立字段 |
| 复权收益污染涨跌停判断 | 调整价只算因子，原始价只判交易性 |
| 北交所规则和流动性差异 | 全量入库、独立榜单、独立阈值 |
| 场外基金 NAV 前视 | 同时保存 `nav_date` 与 `ann_date`，按首次可用时间回测 |
| 基金份额重复霸榜 | 仅在 provider 明确给出份额关系和完整费率时聚合；否则保持真实份额独立并标记关系未知 |
| 每日推送过多 | 主动推 Top3 总览，完整 Top10 按需查询 |
| 当前没有人民币账户 | 不生成数量、融资或自动交易建议 |
| 历史规则变化 | 版本化成本、涨跌停、交易单位和结算元数据，不硬编码单一规则 |
| 点时行业/ST/份额关系不可得 | capability 预检；缺失区间不回填当前值，降为板块/市值标准化或不可回测 |
| AKShare 字段能力不完整 | 按榜单维护 capability matrix；缺关键字段时禁用该类回退而非拼凑 |
| 综合卡关联多个榜单 run | 用 immutable bundle 与 bundle-runs 关联表，outbox 引用 bundle |
