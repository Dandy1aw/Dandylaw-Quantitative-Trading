# 策略验证与扫描闭环加固设计

日期：2026-07-08

## 目标

修正当前研究中同一根日线收盘生成信号并按同一收盘成交的乐观偏差，让全市场扫描真正产生可统计的固定持有期结果，并降低 IEX 部分成交量和极端值对横截面排名的影响。排名缓冲、绝对动量门槛只进入滚动样本外实验，未经证据不改变生产决策。

## 方案选择

采用“共享执行模型 + 独立扫描评价 + 实验门禁”方案：

1. 回测信号仍使用当日收盘及以前的数据，目标权重延后一根交易日，并以次日开盘成交；单边手续费和滑点各 5bp。
2. 全市场扫描若主数据源声明成交量为部分市场数据，则日线扫描改用 yfinance 完整市场成交量。获取失败时本次扫描失败关闭，不回退到有系统偏差的 IEX 成交量排名。
3. 扫描三因子先做 5%/95% 截尾，再转成百分位排名，避免普通 z-score 被少数异常值支配。权重保持 40/30/30，不做参数寻优。
4. `market_scan` 不再依赖不存在的 SELL 信号。周报按“信号后下一交易日开盘买入、持有 20 个交易日、期末收盘卖出”生成虚拟交易；未满 20 日显示为未平仓。
5. 新增真正的滚动样本外研究：训练窗选择候选参数，后续测试窗只评价一次；同时保留原 `walkforward.py`，但改名义为确定性/未来函数检查，避免把它误称为 OOS。
6. 排名缓冲和绝对动量门槛作为候选参数进入 OOS。只有多数测试窗同时改善换手与风险调整收益，且年化差异超过既有 5pp 时点噪声带，才允许另行上线。

## 数据流

盘后日线 → 当日收盘生成信号 → 目标权重 `shift(1)` → 次日开盘撮合 → 收盘估值。

全市场代码 → 完整成交量日线初筛 → 130 日完整历史 → 稳健百分位三因子 → Top1 入台账 → 20 交易日固定期限评价。

## 错误处理

- 次日无开盘价的标的不成交，不用收盘价替代。
- 扫描完整成交量源失败或返回空数据时跳过整次扫描并记录原因。
- 固定期限评价缺少下一交易日开盘价时跳过该信号；未到期只按最新收盘计算浮盈。
- 历史数据不足、价格或成交量非有限值的标的在评分前剔除。

## 验收标准

- 单元测试证明权重只在下一根 bar 生效，成交价使用开盘价并包含成本。
- 单元测试证明异常成交量不会单独劫持排名。
- 单元测试证明扫描信号按下一日开盘进入、20 个交易日后关闭。
- 既有测试、完整 pytest、mypy 全部通过。
- 研究报告明确标注 point-in-time 成分缺失、幸存者偏差和执行假设。

## 范围外

本轮不重新测试已证伪的紧止损、个股反波动率、组合波动率目标和调仓错峰；不声称当前股票池消除了幸存者偏差；不接自动下单。
