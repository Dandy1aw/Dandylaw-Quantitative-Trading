# 安全与运维治理

## 凭证轮换

`api.txt` 曾被 Git 跟踪，因此其中出现过的 Alpaca 凭证必须视为已经泄露。处理顺序：

1. 在 Alpaca 控制台创建新凭证。
2. 只把新值写入本机 `config/.env`，不要写入聊天、日志或仓库文件。
3. 重启服务并验证行情拉取成功。
4. 立即撤销旧凭证。

CI 会运行 `scripts/check_secrets.py`，阻止 `api.txt`、`config/.env` 或明显的非空凭证赋值再次进入版本库。

清理 Git 历史会改写所有相关提交并要求强制推送、所有协作者重新克隆，因此必须单独安排维护窗口并获得明确授权。建议使用 `git filter-repo --path api.txt --invert-paths`，完成后检查所有分支和标签，再强制推送全部受影响引用。即使清理历史，也不能替代凭证轮换。

## 飞书代理

需要代理时，在 `config/.env` 配置 `FEISHU_PROXY`。支持 `http`、`https`、`socks5` 和 `socks5h` URL；该配置同时覆盖飞书 REST 请求与长连接。留空则保持直连。

## 任务运行记录

调度任务的开始时间、最近成功、最近失败、耗时、脱敏错误和连续失败次数持久化到 `signals.db`。进程重启后健康检查会恢复这些状态。关键 pipeline 明确返回 `False` 时按失败处理，不再把“推送失败但函数正常返回”记录成成功。

## 本地与异地备份

每日维护任务继续把 SQLite 台账和可用的 DuckDB 行情缓存写入 `data/backups/YYYYMMDD`，并生成包含大小与 SHA-256 的 `manifest.json`。

在 `config/.env` 设置 `BACKUP_MIRROR_DIR` 后，同一份备份会复制到仓库和 `data/` 目录之外的镜像位置。该位置应由同步盘、NAS 快照或异地卷进一步复制。首次人工验证恢复后，把 `backup.require_mirror` 改为 `true`，此后镜像缺失会令维护任务明确失败并进入告警。

至少每季度做一次恢复演练：复制镜像到临时目录，校验 manifest，打开 `signals.db` 并确认 schema 版本和近期任务记录可读。

## 后续数据与绩效口径

历史回放必须使用当日可见的指数成分、财报和公司行动数据，并记录每份数据的 `effective_at`、`known_at` 与来源版本；没有这些字段的当前快照不能标为 point-in-time 回测。`quant_signal.point_in_time` 已实施 `pit-membership-v1` 校验，旧的日期到代码列表只能继续作为探索性过滤，不能再清除幸存者偏差标记。

合格的指数成分数据形态如下，实际文件还必须覆盖完整回放区间：

```json
{
  "schema_version": "pit-membership-v1",
  "source": "licensed-provider",
  "source_version": "dataset-2026-07",
  "snapshots": [
    {
      "effective_at": "2026-07-20T00:00:00Z",
      "known_at": "2026-07-19T20:00:00Z",
      "members": ["AAPL", "MSFT"]
    }
  ]
}
```

执行绩效以券商成交回报为唯一成交事实，信号价和计划价只能用于衡量滑点。当前实现会跨账户快照持久保留券商聚合成交，并按 FIFO 报告已实现毛收益；Alpaca PAPER 明确标为模拟源，截图没有成交明细时不会推测交易。要升级为真实净收益，仍需接入实际券商成交明细中的部分成交、费用、汇率和公司行动。
