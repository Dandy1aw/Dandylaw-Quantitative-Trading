# quant-signal 重构方案：缺陷清单与重构计划

日期：2026-07-08 · 分支：feat/v0 · 状态：**工作区当前是破损半成品（16 个测试挂）**

本文档记录项目当前的缺陷、用户未考虑到的风险点，以及分阶段多 agent 重构计划。
写作原则：只写核实过的事实（标注文件:行号），不写臆测。

---

## 一、现状快照

- **规模**：src 2476 行 / tests 2097 行 / research 1513 行，137 个测试（绿灯时）。
- **架构**：单进程 APScheduler 常驻（Windows 计划任务 + supervisor 重启循环），
  `Engine` 编排 数据(Alpaca IEX+yfinance) → 4 策略 → 趋势闸门 → 去重 → sqlite 台账 → 飞书卡片。
- **中断点**：上次会话在做"扩池到 32 只 + 动量 rank() 抽取"时中断——
  `momentum_rotation.py generate()` 引用了已移入 `_compute()` 的 `close` 变量（NameError），
  16 个测试挂。`settings.yaml` 的 universe/asset_type 已扩好但未提交。

## 三、重构计划（多 agent）

原则：**先恢复绿灯，再交付用户功能，再修正确性，再修可靠性，最后动大架构**。
每阶段独立可验收：全套 pytest + mypy 绿、关键路径端到端真跑、独立提交。

### Phase 0 · 止血（主线程直接修，不发 agent）
完成中断的 rank() 重构（`last_ts` 改从 bars 索引取），恢复 137+ 测试绿灯，提交扩池配置。

### Phase 1 · Top5买/Top3卖榜单（用户直接要的功能，最先交付）
- 新增「动量全池榜单」卡：全池按动量降序 **Top5 买入候选** + **Bottom3 卖出警示**（持仓中标的标注 ⚠持仓）。
- **决策**：实际选股逻辑（组内名额，回测验证过）不动；榜单是**展示层**，基于 `rank()` 全池排名。
  卖出警示 = 全池动量最差 3 只 + 持仓中趋势闸门 FLAT 的标的。
- 对 32 只新池重跑动量回测，如实报告新池 vs 旧池差异（新池含 Mag7 会稀释半导体集中度）。

### Phase 2 · 正确性修复（D2/D3/D4）
- D2：汇率失败 **fail-fast**——取不到汇率的币种，其标的直接从合格池剔除并记 warning（宁可漏选不可错选）。
- D3：历史不足的标的**显式剔除出闸门保护并在卡片标注 ⚠数据不足**（而非静默视同 LONG）。
- D4：config 加 pydantic 校验：universe 里每只美股必须在 asset_type 里、外币必须在 international_tickers 里，启动即验，缺配置直接拒绝启动。

### Phase 3 · 可靠性（D5-D10）
- D5：关键 job 配 `misfire_grace_time`（premarket/rotation 1h，intraday/deviation 4min）。
- D6：改为**先推送后写台账**（推送失败不记 pushed，下轮重试；重复推送风险由 dedup 键天然兜底）。
- D7：告警加静默窗口——同一 job 的失败告警 2 小时内只发一次。
- D8：live price 改批量 `yf.download(所有票)` 一次拉齐。
- D9：enrichment 超时降到 60s、失败票跳过不重试。
- D10：supervisor 日志加 14 天清理。

### Phase 4 · 架构拆分（D11-D14/D17，动最大，最后做）
- ticker 注册表：`universe` 改为 `ticker -> {asset_type, currency}` 单一来源，派生出旧字段（向后兼容）。
- engine 拆为 pipelines/（premarket/intraday/deviation/enrichment 各一个模块），Engine 只装配依赖。
- 测试 fixture 独立化：`tests/conftest.py` 提供 `test_settings()`，不再读生产 yaml。
- 去重配额分策略：premarket 报告类与盘中告警类分开限流。

### 暂不做（明确记录，避免范围蔓延）
- D15 回测/实盘统一（价值高但工程量大，等 Phase 4 稳定后单独立项）
- D16 ledger 迁移框架（当前 schema 稳定，等真有加列需求再上）
- D18 持仓成本价（需要用户录入真实成交，产品形态待定）
- D21 SIP 付费数据（等策略上盘中级别再评估）

### 多 agent 编排

| Wave | Agent | 范围 | 隔离 |
|---|---|---|---|
| 0 | 主线程 | Phase 0 止血 | - |
| 1 | Agent-榜单 | Phase 1（momentum/cards/engine 一小块 + research 回测） | worktree |
| 1 | Agent-正确性 | Phase 2（fx/trend_gate/config，与榜单文件基本不相交） | worktree |
| 2 | Agent-可靠性 | Phase 3（scheduler/deploy/engine 推送顺序） | 主树 |
| 3 | Agent-架构 | Phase 4（engine 大拆分，等前面全部合并后） | 主树 |

每个 agent：TDD（红→绿）、`uv run pytest` 全绿、`uv run mypy src/` 干净、按 phase 独立提交。
Wave 1 两个 agent 并行后由主线程合并、跑全套回归、真实端到端验证（premarket 推一次飞书）、重启服务。

## 四、验收标准

1. 全部 phase 完成后：测试 ≥150 个全绿，mypy 干净。
2. 端到端：run_premarket 真实推送含新榜单卡；偏离/告警链路真实验证。
3. 新池回测报告落 `research/reports/`，如实报告（含小样本/幸存者偏差声明）。
4. 服务重启后 24h 观察：定时任务零异常（有 JobHealth 兜底告警）。
